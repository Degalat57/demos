# Historic Burial Records Archive (demo): details

A searchable public archive of historic burial-company records from a fictional river-valley region, 1900–1965. Visitors search transcribed details (names,
dates, counties), open a record, and view the scanned ledger page. Staff add
records from a CSV spreadsheet with validation and preview.

**Every record and scan in this demo is a SYNTHETIC SAMPLE — not a real
record.** Data is generated by `gen_records.py`; names, dates, cemeteries and
scans are fictional and must not be used as historical or genealogical
sources.

## Run locally

```sh
python3 gen_records.py
python3 -m http.server
```

Then open <http://localhost:8000/>. The app is static (HTML + vanilla JS +
CSS, no frameworks, no CDNs) and runs from any static host. `gen_records.py`
uses only the Python 3 standard library and is deterministic
(`random.seed(1927)`), so it regenerates identical data.

Generated files:

- `data/records.json` — 200 synthetic records
- `data/scans/<record_id>.svg` — one ledger-page scan per record
- `data/sample-import.csv` — 25 rows for testing the import page, exactly 4
  with deliberate problems (missing surname, impossible date `1931-02-30`,
  unknown county "Atlantis", duplicate `record_id`)
- `data/sample-import-clean.csv` — 10 valid rows

## Data model

Each record (`data/records.json`) has:

| Field | Example |
|---|---|
| `record_id` | `HBR-1934-0172` (`HBR-<year>-<4 digits>`) |
| `surname`, `given_names`, `maiden_name` | `Johnson`, `Robert Lee`, `""` |
| `sex` | `M` / `F` |
| `age_at_death` | `62` or `""` |
| `birth_date` | ISO date, 4-digit year, or `""` |
| `death_date`, `burial_date` | ISO dates; burial 0–5 days after death |
| `county` | one of 11 fictional counties |
| `place_of_death` | town in that county |
| `cemetery` | fictional, e.g. `Mt. Zion Cemetery (fictional)` |
| `funeral_cost` | `$45.00` or `""` |
| `informant` | fictional name |
| `ledger_book`, `ledger_page` | `Book 7`, `112` |
| `notes`, `transcriber` | short note or `""`, `Volunteer A` |
| `scan` | `scans/HBR-1934-0172.svg` |
| `synthetic` | `true` (always, in this demo) |

Staff-imported records are stored in `localStorage` under
`archive-imports-v1` and merged with `records.json` at load time; they carry
an "added by staff (this browser)" badge.

## Pages

- `index.html` — search: name (with fuzzy matching for handwriting variants
  such as Johnson/Johnston), county, death-year range, sort, pagination,
  shareable URLs, CSV export.
- `record.html?id=...` — full transcription, citation with copy button,
  prev/next navigation from search results, and a scan viewer with zoom,
  rotate, pan and keyboard controls.
- `import.html` — staff CSV import: RFC 4180 parsing, header aliases, per-row
  validation (required fields, real calendar dates, burial ≥ death, county
  list with suggestions, unique IDs, age 0–120), preview table with
  ok/warning/error statuses, import of valid rows.
- `about.html` — collection description, citation guidance, and an
  explanation of the "SYNTHETIC SAMPLE" marking.

## Maintenance notes for a large dataset (100k+ records)

- Move search server-side (Postgres trigram/GIN index, or Datasette) —
  shipping 100k+ records as JSON to the browser stops being practical.
- Alternatively, keep the static approach with a pre-built, sharded index
  (e.g. by decade or county) loaded on demand.
- Regenerate the search index as part of the import pipeline rather than at
  page load; version the data files so CDN caches can be invalidated.
- Keep scans behind object storage with long cache headers; add tiling
  before ingesting high-resolution page images.
- Re-run the synthetic-data generator (`python3 gen_records.py`) any time to
  reset the demo to a known state.
